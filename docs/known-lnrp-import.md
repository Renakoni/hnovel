文件读取上限为 16 MiB；普通 JSON 仍使用原导入大小上限。未知包、未知版本和损坏文件显示不支持的包版本提示。ZIP 魔数也参与分流，改扩展名不能绕过识别。本次只增加本地文件入口，URL 下载插件包仍不受支持。

映射定义固定使用标准 Legado profile。更改 JSON profile 选项不会给同一个包创建另一套来源身份。预览、逐项选择、已有来源版本比较、身份映射、授权与原子提交均复用既有流程；识别文件本身不会激活来源或授予网络权限。

适配规则随应用版本发布。更新应用后重新导入同一文件，可以预览新的定义修订；同一 profile 与 import key 保留 source ID，重复相同定义的提交是 `Unchanged`。域名或来源身份变更仍需既有的显式身份映射与重新授权流程。原插件的更新机制不参与这些定义的更新。

分类名称与链接来自本次实际获取的站点导航，并作为维护快照随定义发布；进入分类后请求真实列表。分类目录本身不额外下载整页再执行脚本。站点导航变化时需要更新定义。

| 来源 | 请求与责任边界 |
| --- | --- |
| 爱丽丝 | 分类、搜索使用桌面 UA；详情、目录、正文使用手机 UA。正文匹配当前手机页 `#chapterContent .content_txt`，无需运行旧插件的 browserGet。 |
| 八叉 | 分类路径使用从 0 开始的页码。搜索从当前查询的 302 Location 获取 searchid，游标不写入全局共享状态。正文从章节页解析五个参数，带章节 Referer、Origin 和表单编码 POST 到公开正文接口；拒绝空或失败响应。 |

| PotatoLib | 仅建立已识别的来源身份，缺少经验证的在线接口时保持停用。2026-09-13 的公网 DNS 返回 NXDOMAIN；公开仓库检索没有找到可确认的迁移源仓库。以后可以在保留 import key 的前提下维护定义。 |

额外图片站点仍通过现有的来源域名授权流程。在线抽样实际验证了主站权限不足时拒绝封面请求，以及用户批准单个图片 origin 后重新读取成功。

## 实际执行与边界

两个原始私有文件均实际通过生产 `SourceDefinitionImporter.previewFile` 导入，分别得到 1/4 个候选；扩展 profile 选择、重复导入及既有身份匹配均已验证。

下表为 Android API 35 上生产 `RuleSource → AndroidIsolatedExecutor → Binder → 隔离进程 → SourceBroker` 的结果；不是外部 HTTP 选择器推测。测试使用一次性的定义存储与会话，未安装这两个插件。

| 来源 | 分类入口数 | 列表第 1/2 页 | 搜索第 1 页 | 抽样目录章节 | 抽样正文字符 | 可解码封面字节 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 爱丽丝 | 30 | 50 / 47 | 10 | 6 | 46,911 | 19,506 |
| 八叉 | 9 | 20 / 20 | 20 | 28 | 1,159 | 31,050 |
| 疯情 | 20 | 30 / 30 | 15 | 42，另保留分卷 | 4,475 | 54,602 |
| Jm18 小说 | 15 | 48 / 48 | 48 | 8 | 5,353 | 37,840 |

分类两页的书籍 ID 集合不同；JVM 补充实测也核对了搜索分页。封面通过 Android BitmapFactory 解码确认。未声称覆盖登录、付费内容、全部书目或长期可用性。

本机系统 DNS 由代理返回 198.18/15 Fake-IP，生产 broker 明确报告 AddressDenied。上述成功链路通过测试参数注入本次实际查询的公网 DNS；应用默认 DNS、地址校验和代理策略保持既有行为。此环境差异不作为站点失败或登录失败处理。

真实页面与图片暴露了原有预算不一致：

- 执行输入单独限制为 512 KiB，足以承载本次 300–400 KiB 网页；JVM 与 Android 共用限制和 JSON 深度预检。隔离进程仍负责解析页面。
- 输出及反向桥接消息继续限制为 256 KiB。标准脚本数据基线为 64 KiB；宿主已声明更大结果预算时，脚本数据与响应读取相应增加，最多 192 KiB。
- 超大页面、目录或图片仍明确返回 Limit；例如超过既有图片数值数组预算的封面不能承诺解码成功。不会截断正文后伪报成功，来源脚本不能自行扩大预算。
- 小结果预算不缩减原有的 64 KiB 输入基线；读取许可、撤销、超时、内存监控与单个活动 worker 的职责不变。

验证包括 135 个来源模块 JVM 测试、26 个 Android 隔离回归测试，以及 2 个 Android 页面大小/真实来源测试。合成回归覆盖实际封面量级的 37,840 字节加解密和超过 64 KiB 的正文响应；原始包、小说正文、账号信息不进入仓库。

## 上游与维护依据

实际核对 [Hoohoo 源码固定版本](https://github.com/limao996/LightNovelReaderPlugin-HoohooLib/tree/87721f078c1171500281dd76dad169893397090f) 与 [发布仓库固定版本](https://github.com/limao996/LNR-HoohooLib-Repo/tree/77bbf94722c5249323cda75fd8eeec7421c34858)。源码仓库未声明许可证；本次依据实际公开页面和请求协议独立编写 JSON 规则，没有复制插件源码。

维护者修改资源后应同时运行 `KnownPluginPackagesTest`、`KnownSourceRulesTest` 和执行边界测试。真实站点验收由 `KnownSourceExecutionInstrumentedTest` 的显式 opt-in 参数触发；DNS 对照仅属于测试会话。
