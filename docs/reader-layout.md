# 正文布局与字体

本次以 main `7acb54fb` 为调研基线，主目标是 [#60](https://github.com/Renakoni/hnovel/issues/60)。上游 [#390](https://github.com/dmzz-yyhyy/LightNovelReader/issues/390) 要求把字体、字号、字重和间距放进可预览的布局页。共享排版、独立段距及重排定位先由 [#66](https://github.com/Renakoni/hnovel/issues/66) 的独立 PR 提供；本 PR 在其上提供统一布局入口、实时预览和字体选择，只关闭 #60。公共排版语义和验证入口见 [独立行距与段距](reader-spacing.md)。

## 调研结论与工作清单

原有 ReaderSettings / SettingState 已经持久化字体 URI、字号、附加行高、字重和边距，不需要新建通用设置框架。缺口是段距、共同的数值约束、完整页面预览，以及布局变化后的内容定位。

旧 TextPagination 逐项读取设置并维护自己的 TextMeasurer；绘制使用另一份 MaterialTheme 样式。FlipPaginationCoordinator 的失效键只能决定何时重跑，不能保证测量与绘制得到相同的输入。原分页适配器逐个调用组件 split，直接把每个短段落变成一个组件会导致一段一页。FlipReadingProgress 则按总页数百分比重排定位。

## 责任边界

- `ReaderLayoutValues` 定义单位、默认值和合法范围。SettingState 在存储读取边界使用它保护非有限值；滑块使用同一组范围。`ReaderLayoutSettings` 是不可变且检查约束的排版快照，不拥有数据库或协程。
- `rememberReaderTextLayout` 解析当前字体、locale 和 TextStyle，并捕获当前 Compose TextMeasurer。内置正文与分页都消费这份输入，不在同一次分页中再次查询字体设置。颜色仍在绘制时解析，换色不触发重分页。
- `layoutReaderText` 负责逻辑段落、实际行高、段距和页面装填。`ReaderTextFragments` 负责保留选择能力的 Compose 文本绘制。使用 `LineBreak.Simple` 和不裁剪首尾行高的样式，避免页面切片改变一行的测量含义。
- `paginateReaderComponents` 只对宿主内置 SimpleTextComponent 使用新排版。图片、错误及插件组件保留原顺序和独立页面，插件的 split 协议、反射构造器和序列化内容不变。
- `ReaderPage` 的范围属于宿主运行时页面，不写回原章节 JSON。FlipPaginationCoordinator 继续拥有取消与最新结果发布；FlipReadingProgress 继续拥有保存进度及章节恢复。
- ReaderLayoutSettingsPage 和主题设置复用字体选择、排版控件、页面预览；没有引入全局设置注册器、预设管理器或下载字体框架。

## 配置与兼容

| 设置 | 单位 | 默认 | 范围 |
| --- | --- | --- | --- |
| 字号 | sp | 15 | 8–64 |
| 字重 | Android weight | 500 | 100–900 |
| 行距 | 附加 sp | 7 | 0–32 |
| 段距 | sp | 0 | 0–64 |
| 手动上、下边距 | dp | 12 | 0–128 |
| 手动起、止边距 | dp | 16 | 0–128 |

`lineHeight = fontSize + lineSpacing` 保留原设置语义；段距写入 `reader.paragraphSpacing`，不修改行距值。旧用户缺少新键时段距为 0，不额外插入间距。有效有限数值超出范围时夹紧，NaN/Infinity 回落到相应默认值。存储内的非法历史值不会被读取动作擅自重写。

滑动过程中更新本地预览草稿，松手后保存该项；字号、间距和边距保留 0.5 单位精度，字重按 100 调节。自动边距继续复用系统遮挡区域与阅读指示器预留。预览按完整窗口尺寸测量同一正文，再统一缩小绘制；翻页预览显示同一分页算法得到的第一页。预览画布高度限制为可用高度的 35%，最多 204 dp，让较矮窗口仍保留控件的滚动和触控空间。

### 段落与特殊内容

现有 `simple_text` 协议只有字符串，没有 HTML p/br 或标题级别信息。因此本次明确兼容规则，而不从标点、缩进或行长猜测段落：

- LF / CRLF 表示段落边界；自动折行是段内换行，已有 U+2028 保持软换行。
- 连续空行保留为空段落；末尾的换行符终止当前段落，不额外产生一个空段落。原始字符范围包含分隔符，能够逐项重建原文。
- 段距只在同页相邻段落之间计入一次，包括相邻内置文本组件之间。跨页延续一个长段落时不重复增加段距，新页顶部不留下段距。
- 空白段落本身保留一个文本行盒，不把显式空行折叠成段距，也不删除用户文本。过小视口仍消耗至少一整行，避免不前进的分页循环。
- 图片与插件组件不使用正文段距填充，其前后不额外加正文段距。内置文本形式的标题使用相同规则；滚动模式原有章节导航标题属于界面装饰，保留原布局。

来源在更早阶段已经丢失的 HTML 软换行/段落差别无法从旧字符串恢复，本 PR 不宣称重建了这些语义。

### 阅读位置

同一章节内容在字号、字体、间距、边距或当前窗口测量输入变化前，捕获可见页的首个内容项和 UTF-16 字符偏移。新分页查找包含该偏移的页面；连续修改期间保留待恢复锚点，仅最新请求能够发布。已有章节保存进度恢复优先处理尚未完成的首次读取，正常重排的锚点不被旧页数百分比覆盖。

锚点绑定本次章节内容列表，内容版本更换后不会复用。应用重启的持久进度仍沿用原协议，插件不透明切片以组件片段序号近似定位；本次不建立跨内容修订或跨阅读模式的持久字符定位协议。

## 字体

“跟随系统”使用 Android 默认 FontFamily。系统向第三方应用提供主题字体时可跟随；部分厂商只替换自家应用字体，没有统一 Android API 能枚举或强制读取这些主题字体。文件导入继续支持用户能通过系统文件选择器访问的 TTF / OTF。

| 字体 | 固定来源 | 字形映射数 | 文件大小 | SHA-256 |
| --- | --- | ---: | ---: | --- |
| 思源宋体 CN Regular | Adobe Source Han Serif `2.003R`，`SubsetOTF/CN/SourceHanSerifCN-Regular.otf` | 30,930 | 11,626,108 bytes | `3754ea669c530e2473354f8f6d9f79680a44d7e26ec7d00eeabee4a7e0753c5d` |
| 霞鹜文楷 Lite Regular | LXGW WenKai Lite `v1.522`，`fonts/TTF/LXGWWenKaiLite-Regular.ttf` | 25,598 | 13,872,424 bytes | `140c99ba4e28e817cec49bf82a0c5fcdc4fe633fb9dfda16d0ee8d59a8545f15` |

两款都是原版字体，未裁剪、改名或修改内部字形。为控制安装包体积只内置常规字重，其他字重由 Android 合成；不声称提供全部原生字重。已检查简体、繁体、英文及西里尔样例字形；完整字体不包含的字符继续依赖 Android 回退。

字体及完整 SIL OFL 1.1 授权随 APK 离线分发，布局页可查看授权。上游链接：[思源宋体](https://github.com/adobe-fonts/source-han-serif/tree/2.003R)、[霞鹜文楷 Lite](https://github.com/lxgw/LxgwWenKai-Lite/tree/v1.522)。两份原始文件共约 24.3 MiB，最终 APK 增量取决于打包压缩。

系统字体仍使用原 `Uri.EMPTY`，两款内置选择使用固定 `reader-font:` URI，旧文件 URI 无需迁移。宿主统一字体加载器识别内置 URI，插件二进制接口不变。导入先复制并用 Android Typeface 校验，成功后才切换到新文件 URI，失败保留原选择。每次有效替换会使字体测量缓存失效。自定义字体解析为已加载的 Typeface，旧分页不再依赖被替换的文件；丢失或损坏的字体回退系统字体。

## 验证

`ReaderLayoutInstrumentedTest` 包含 5 项 Android 验收：系统/两款内置字体在不同宽度、页高及字体缩放下的真实度量；换字体后的字符范围；旧字体键与损坏文件回退；拖动时实时预览、松手后保存及字体切换清理；250 dp 高窗口内间距与手动边距滑块完整可见且能持久化。亮色、暗色和紧凑窗口截图由测试生成。

依赖 PR 的 `ReaderSpacingInstrumentedTest` 包含 4 项共享管线验收，覆盖实际滚动、实际 Pager 连续重排、文本绘制与测量一致性，以及图片与相邻文本边界。JVM 回归覆盖设置、段落分页、字符完整性、分页取消、重排进度、旧插件渲染和音量键。

最终命令、各分支测试计数及 API 24 / API 35 CI 结果记录在对应 PR；字体资源的 SHA-256 已与上表核对。
