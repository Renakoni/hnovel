## 一致性与设计原则

- 书籍主键始终是来源与远端书籍身份。修订和账号代次属于执行/认证，不创建或删除另一份书架。两个来源的同名同作者书籍保持独立。
- Account 存储只放专用登录信息，来源通用 KV、规则书籍状态和资源持久数据跨账号保留。Cookie、LoginInfo/LoginHeader 的删除是认证切换，不与缓存删除绑定。
- 图片按来源、书籍、角色、地址与处理修订缓存，不包含账号或认证头。已撤回账号图片登记、淘汰和迟到图片删除机制，也移除了随 Cookie 变化清空 HTTP 缓存的无效框架。
- 来源状态的改变由注册表/执行票据撤销旧任务；持久化修订提交与运行时发布保持同一所有者。更新、回退后的配置编辑使用安装快照，避免被失败导入的候选版本阻断。
- 管理页只编排已有服务。批量激活不宣称全有或全无；失败时保留成功项、刷新列表、废弃过期预览。导航由目的地传入回调，诊断入口不让可测试的页面直接依赖全局导航。
- 手动清理只操作章节正文 DAO 与 Coil 缓存，保留目录、书架、阅读记录、设置和认证状态，不调用会删除用户记录的通用 clear。
- 浏览器是网络层的窄执行端口，Android 实现放在适配层。诊断通过生产 trace 获取元数据；搜索与发现页面共用列表解析，未复制解释器。没有引入通用 Settings 框架、账号图片策略或额外来源选择模型。

- 登录分支 `account-host-verified.log`：Coil、来源激活和登录回归；`cache-policy-simplified.log`：Cookie/HTTP 缓存语义简化后的网络测试。
- 浏览器分支 `browser-release-build.log`：规则、网络、执行、Rhino 模块及 APK 构建；`browser-accepted-5556.log`、`browser-accepted-5558.log`：API 24 / API 35 各三项真实 Chromium 测试通过。
- 管理分支 `management-host-verified.log`：导入、配置回退、Compose 页面、真实 Room 手动清理保留阅读数据；批量失败恢复在最终整合测试中补验。
- 诊断分支 `convergence-accepted.log`：生产内容/网络模块、七组宿主连接回归与最终 debug APK 构建。包括发现规则实际执行、取消后临时状态回收、正常会话保持及合成秘密不外泄。

浏览器支持范围与请求预算见 PR #120 正文；本检查点不把有限的网页 API 支持描述成任意网站兼容。全格式真实来源组合验收仍由 #95 承接。本批发布后不等待远端 CI/review。
