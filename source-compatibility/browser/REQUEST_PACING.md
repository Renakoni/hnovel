# 来源请求节奏（#186）

来源填写 `concurrentRate: "1/2000"` 后，普通 HTTP 和原生导航共用每两秒一次的准入节奏。
规则解析、目录/正文分页、预取和下载只要通过同一 SourceSession，就共享状态。
这使书源声明真正影响实际调度；没有证据表明仅靠限速可以消除 Cloudflare 验证。

## 参考语义与取舍

对照固定版 MD3 `fb01a76` 的 `ConcurrentRateLimiter.kt` 和 `AnalyzeUrl.kt`：

| 输入 | 运行语义 |
|---|---|
| null、空文本、0 | 不增加来源限速 |
| 正整数 M，JSON 数字或文本 | 每 M 毫秒一次，不是并发 M 个 |
| 正整数 N/M | 从首次实际准入起算，每 M 毫秒窗口最多 N 次 |
| 非法文本、非正数、溢出 | 不增加来源限速；导入保留原值，既有 broker 硬限制仍适用 |

允许首尾空格；间隔为正 Long 毫秒、次数为正 Int。原参考实现对部分错误次数会回退成 1，
本实现明确停用非法配置，不复制隐式纠错；JSON 的对象、数组、布尔、非整数数字仍由导入器拒绝。
N/M 保留参考的固定窗口语义，允许窗口内 N 个请求；不是平滑令牌桶，不承诺任意滑动窗口内也最多 N 个。
计时使用单调时钟，过期后以当前实际准入时刻重开窗口，不累加空闲窗口额度、不预订未来槽位。

## 责任边界

- `RuleSourceDefinition` 读取原字段，`RuleSource` 配置会话；不新增设置体系或脚本可修改的限速入口。
- `SourceRequestPacer` 只负责解析后的窗口状态和可取消等待，等待者醒来后重新检查额度。
- HTTP 在缓存检查、并发许可和原 broker 最小间隔之后申请准入。每次重试重新计数；一条请求的重定向链算一次来源请求，逐跳权限与 broker 硬间隔继续执行。
- `NativeSourceBrowser` 在取得独占执行窗口并完成服务绑定后、`remote.start` 前申请准入。不能在串行锁外提前计数，否则长时间人工验证后可能集中发出积压请求。
- 旧合成浏览器对真实顶层入口计数一次，自己的 HTTP 桥接子请求不重复计数；传入 HTML 没有顶层网络请求。
- 原生页面的重定向、iframe、fetch、Worker、图片及站点脚本请求由 Chromium 自行处理。本限速器不会插入它们的网络路径。
- 应用 HTTP 缓存命中、data URL、宿主封面加载不消耗来源额度。WebView 是否命中其内部缓存由 Chromium 决定，宿主仍对每个原生导航计数。
- HTTP 与原生浏览器共享限速状态，但 Cookie 仍各自管理；共享限速不会桥接登录状态。

额度属于活跃的来源/账号会话，不是全 App 全局锁。账号代次或来源修订替换会话时，旧等待者取消，
新会话重新开始计数；不将上一账号的等待迁移到下一账号，不持久化窗口或积压请求。
重复配置同一速率不会清空当前窗口。既有请求/规则总预算仍包含限速等待，长间隔可能触发既有超时，
不会因来源写入大数值而无限延长解析预算。

搜索的 query/来源/账号改变继续使用既有 generation 取消旧工作；取消传播至 broker 等待者。
前台交互请求沿用 #188 的独立所有权，不为了全局 URL 去重而合并不同用户操作。
验证恢复最多重试一次；后台遇到挑战结束并提示。限速器本身不刷新页面、不启动恢复循环。

## 验证

- 受控时钟：6 项，覆盖空值、裸间隔、固定窗口、非法值、并发等待者、空闲窗口、取消不占未来额度和延迟唤醒重新计时。
- 本地 HTTP/浏览器边界：5 项，覆盖实际发送间隔、重试/重定向、缓存/data/子请求、取消与账号替换、浏览器锁内准入及 HTTP 共享窗口。
- 生产规则字段接线：1 项，JSON 数字和文本都进入浏览器会话的同一准入接口。
- MuMu 原生时序测试通过：前台自有页面等待时排队后台导航，中途取消一项，并发发出显式 API 请求。单项实测请求间隔 `[1963,2033,1956]` 毫秒，iframe/fetch 最大延迟 `[182,273]` 毫秒；整组回归再次测得 `[1997,1999,1995]` 和 `[176,203]`。取消的排队请求均未发出。这里是服务端到达时间，包含 Binder、WebView 和网络调度差异，不把每个到达间隔都描述为严格大于 2000 毫秒。
- 最终全量 JVM：843 项通过（app 418、七个 source 模块 425），无失败/跳过。MuMu 原生浏览器和生产验证恢复组 11 项通过、1 个未启用的环境探针跳过；新增时序测试已随 NativeBrowserInstrumentedTest 纳入 API 35 CI。
- 参考源 3 项 Node 回归通过。真实 hlib 保留现有账号（generation 0）尝试一次搜索，在 8.66 秒后返回 `BrowserRequired: searchUrl`，没有继续批量请求，不计为完整读取通过。

本地 fixture 使用中性页面，不点击或自动处理外部 CAPTCHA。真实 hlib 使用现有账号，低频有限读取；
若遇到挑战则记录并等待正常人工验证，不能把等待超时当作限速失败或成功的归因证据。

结构化结果见 [pacing-results.json](pacing-results.json)。上游验证恢复 PR #188 的 API 35 首次检查在窗口测试中超时，
该修正在 #188 独立提交并由本分支继承，不纳入 #186 的主要修复目标；各 PR 的远端结论以其检查页面为准。
