# hlib 加载时间与参考项目对照

原生 hlib 源不再默认设置 `concurrentRate: "1/2000"`。该值来自调研时的保守选择，没有站方要求或同条件试验证明需要固定两秒。省略字段沿用宿主已有语义：不增加来源窗口等待；其他来源显式声明的速率仍受支持。

## 三层不同的等待

| 路径 | 当前行为 | 影响 |
|---|---|---|
| 来源请求节奏 | 显式 1/2000 使同一来源/账号两秒内最多准入一次；hlib 现在不默认声明 | 四个快请求的发起时间原来至少横跨六秒；不是每次响应后都额外睡两秒 |
| 后台页面读取 | NativeSourceBrowserService 在 onPageFinished 后等 1000 + delayMillis 再执行规则 | 所有原生文档读取都有固定的一秒等待，和来源限速不是同一个机制 |
| 首页聚合 | RuleDiscoveryProvider.feed 串行读取四个首页预览；DiscoveryPageViewModel 等 feed 完成才发布 sections | 即使单个列表已就绪，用户仍要等剩下的预览 |

两秒窗口和一秒页面等待可能重叠，不能简单相加。网页直接浏览通常先显示当前页面，App 则要取完整文档、解析并聚合结果；应比较同一页面、同账号/缓存条件下的首个可用内容，不能拿四预览首页对单页的时间当作纯网络差距。

## 参考 MD3 fb01a76

- `help/ConcurrentRateLimiter.kt` 同样读取来源字段，空值或 0 不添加该限制；它不是所有网站必须启用的功能。
- `model/analyzeRule/AnalyzeUrl.kt` 仅在请求声明 webView 时创建 BackstageWebView，其他请求使用 HTTP。
- `help/http/BackstageWebView.kt` 同样在 onPageFinished 后等 1000 + delayTime；因此这个固定等待并非参考项目已经完全解决的能力。
- 本地已验证的参考 hlib 源主要为搜索声明 webView；本宿主的 browserRead 将文档请求保留在原生浏览器内，以保持来源账号与 Chromium 会话。路径更多地经过 WebView，也放大了固定等待。
- 参考发现入口先加载分类，点击入口后加载对应列表。本宿主四个默认预览是额外产品行为，后续应保留预览并考虑渐进发布，而非悄悄删除用户要求的四个预览。

## 2026-09-14 MuMu 测量

Android 12 / WebView 110.0.5481.154.1，Debug APK。使用自有回环静态页面与生产 NativeSourceBrowser；前后台各三次，页面通过 Navigation Timing 和自定义结果属性报告已就绪/提取时间。没有注入站点、改浏览器 getter、借取 Cookie 或进行验证码自动化。

六次从 loadEventEnd 到规则提取分别为 **1045.6、1045.2、1016.6、1020.5、1048.9、1045.0ms**。这是固定一秒页面等待的证据，不包含 ADB/instrumentation 启动、宿主最终解析或公网 hlib 网络时间，不能直接换算为实站提速比例。

同期原生时序 fixture 仍正确执行显式 1/2000：请求到达间隔 `[1976,2002,2024]`ms，页面内部 iframe/fetch 间隔 `[161,220]`ms，取消请求为 0。来源等待是可取消协程，不直接阻塞 UI 线程。另一个已加载分类列表的短时滑动样本为 69 帧、0 janky、P95 11ms；不代表所有设备或加载阶段。

## 后续边界

1. 优先使用明确的页面就绪条件；若移除通用一秒宽限，需要验证异步结果、页面重定向、显式 webViewDelayTime、验证恢复及普通无 webJs 来源，不能只改常量。
2. 首页渐进显示需要保持来源/账号、取消与错误归属，避免旧任务结果覆盖新页面；现有四个预览不能退化为只显示第一个。
3. CF 频率应另做同账号、同网络、同 provider 的连续阅读对照。采样包含进程/fixture profile 切换，与普通连续浏览不是同一条件；此配置修正不宣称降低或消除验证。
4. 旧的 REQUEST_PACING.md 和稳定性报告保留其测试时点的 1/2000 证据；它们说明显式配置的实现，不代表当前 hlib 默认值。
