# 首页预览渐进发布

对应 #201。多模块首页此前在全部预览完成后才显示，例如已完成的日榜仍需等待周榜、月榜、文章。本次按来源声明顺序发布已完成的模块，保持其余模块继续加载；总网络请求与单页加载时间没有因此减少。

## 执行与责任

- `DiscoveryProvider.feedUpdates()` 提供累积的替换快照，流结束才表示加载完成，错误是终止结果。缺省实现仅发布既有 `feed()` 的一次结果，已有原生提供者无需改写。`feed()` 的一次性调用契约仍保留。
- 规则提供者对显式 homepageModules 每完成一份预览发布一次；未声明模块的普通分类目录保持只读第一份预览、一次发布全目录，避免数百项分类引发额外请求或平方级快照复制。
- 每份预览最多显示原有的六本书，保持标题、更多入口、分类 ID、源级表单值和文本处理。快照替换列表，不追加重复模块。
- `SourceDiscovery` 在原 runtime 的调度器和生命周期内执行提供者，用 channelFlow 把来源绑定后的快照传回页面。停用 runtime 或取消收集会取消其工作；每次发送前检查 runtime 仍可用。
- ViewModel 在主线程收集，每次结果核对请求 serial 和当前来源。离开页面、切源、刷新、账号/修订变化通过取消并递增 serial 作废旧任务；自己的验证窗口覆盖页面时保留请求，允许窗口关闭/失败结果在页面恢复前落地，避免永远保持 loading。部分成功保持 `loaded=false/loading=true`，流完成才变为完整状态；滚动位置跟随用户当前状态。
- 后续错误保留当前已显示结果，停止加载并显示原有错误/重试入口。刷新从新快照替换，首次新结果前保留旧页面；取消的部分加载不能被当成完整缓存。
- 自动验证属于当前模块的 request 包装；验证通过仅重试失败模块一次，已经发布的模块不重新请求。后台任务及验证再次失败仍遵循原恢复契约。

## 与加载速度、指纹的关系

这是通用规则书源的首份预览显示优化，适用于其他声明 homepageModules 的来源，不是 hlib 标题特判。独立搜索仍沿用现有搜索流，普通 HTTP/API 不增加 WebView 等待。

本变更不修改 WebView 网络、iframe、Worker、UA、Cookie 或页面就绪条件，不并发争用来源账号浏览器。实站 Navigation Timing 已发现第三方资源可能拖延 full load，onPageFinished 后还存在一秒宽限；解决这部分需要明确的内容就绪契约，不能将 DOMContentLoaded 一律视为动态内容完整。CF 频率降低需单独取证。

## 验证入口

- `ExploreHomeViewModelTest`：首份结果可见与可导航、最终完成、失败/刷新、保留滚动、切源取消、账号变化丢弃旧快照、验证失败早于页面恢复时正确停止加载。
- `SourceDiscoveryTest`：流结果绑定原来源，runtime 移除取消进行中的提供者。
- `RuleDiscoveryProviderTest`：首份消费后取消不继续请求、后续失败、快照不被后续修改、验证只重试当前模块；保留大目录单预览测试。
- `ExploreHomeScreenTest`：未完成加载时已收到的书籍和更多入口仍可使用。
- `HlibBrowserLiveInstrumentedTest` 新增显式 `liveHlib=true/hlibAction=feed`，使用现有账号和生产 runtime，断言快照大小依次 1/2/3/4，仅输出模块数量和时间。实站测试需要用户登录，可能请求人工验证，缺省 CI 不运行。

实测结果和其他 PR 的整合状态记录在统一入口 `ref/hlib-adaptation-20260913/README.md`。
