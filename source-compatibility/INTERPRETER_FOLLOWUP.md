## 本轮直接移植的状态语义

| 调用 | 原实现差异 | 参考语义及修正 |
| --- | --- | --- |
| `java.get("bookName")` / `@get:{bookName}` | 只查普通变量，可能读到同名旧值 | 存在书籍时先返回当前 `book.name`；空书名也是有效结果，不向普通变量回退 |
| `java.get("title")` / `@get:{title}` | 同上，且 JS 中修改元数据后读取不一致 | 存在章节时先读当前 `chapter.title`；JS 执行中读活动对象，纯选择规则读同一状态的快照 |
| `java.put` / `@put` | 单独维护临时值，优先于实体变量；实体 API 无法替换它 | 写当前章节，否则写当前书籍；与实体 API 共用变量，后写入的值立即可见 |
| 空变量与大变量 | 清空临时值会重新读出实体中的旧值 | 覆盖当前实体值，空值继续向书籍/来源回退；按参考的 10,000 字符阈值写大小变量存储 |
| 来源回退 | `java.get` / `@get` 未读取 `source.get` 的持久值 | 章节、书籍、传入变量均无非空值后，通过已绑定的 broker 读取来源存储 |
| 无书籍/章节时保存 | 临时值不能由后续来源调用读取 | 经 broker 写 `source.put`；无宿主的纯解释器仍只保存本地测试状态 |
| 搜索第一字段 | 尚未有书名或 URL 时无法辨认当前空书籍 | 像 `BookList` 一样，先创建空书籍状态再解释第一字段，避免将行变量写到来源级 |

## 为什么保留宿主适配，而不是另写解释语义

参考直接持有 Android 的书籍、章节、来源对象和数据库，JS 与选择器都操作它们。
我们的规则运行在隔离进程中，主进程持有来源授权、账号与存储。正确的移植方式是：

1. 在 worker 内复用相同的选择、变量查找顺序和实体行为。
2. 用快照和明确的写入结果跨进程传递实体状态；规则成功后由宿主提交。
3. 来源存储调用经过现有 broker，沿用账号归属、撤销和配额。

这一实现减少了临时变量与实体变量两套状态之间的分歧，同时保留现有进程隔离。
并不声称所有方面优于参考：参考的直接对象模型更简单；我们需要额外验证序列化、
活动对象与快照转换以及调用结束后的状态清理。缺失 API 应按源码实现真实行为，
不能以空函数代替，也不能将网站错误页面当成正文。

## 缓存的持久化和有效期

原来的 `cache.put/get` 使用会话内存，省略有效期时默认 60 秒，显式传 0 会报错。
参考 `CacheManager.put` 把普通值存入数据库：省略有效期和显式 0 均不过期，其他整数
按秒计算截止时间。现在桥接层采用这一语义，普通缓存写入来源/配置档案独立的持久存储，
沿用加密接口、原子写入、容量和条目数限制；来源账号切换和 broker 重建不会丢失这些值。
HTTP 响应缓存仍使用独立的网络有效期。

同步实测发现参考版本也有缺陷：阅读 3.26.15 对 1 秒及负数有效期的普通缓存仍返回旧值。
MD3 的 `CacheManager.get` 先返回内存字符串，不检查截止时间，其源码与此现象一致。
调用 `deleteMemory` 后，参考的磁盘读取结果为：

```json
[[null,"default","zero","short",null],["default","zero",null],null]
```

三项依次是写入后读取（包括缺失键和负数有效期）、1.1 秒后读取、删除后读取。
生产 worker/broker 测试得到同样结果，并额外重建 broker 验证持久化和来源/配置档案隔离。
我们遵循 hectorqin 分支及磁盘存储的有效期语义，不复制 MD3 内存层忽略有效期的行为。

当前以每个来源的受限快照保存普通缓存，读取会解析快照，写入会原子替换快照。
相比参考数据库逐键读写，大量缓存键下的开销更高；需要按实际负载决定是否换成逐键索引。
文件/字节缓存、保留对象身份的内存缓存和数值读取 API 仍需各自适配，不能作为字符串
缓存的别名来声称兼容。

## 详情已经取得的目录交给下一次读取

参考 `BookInfo` 保留目录页面，交给目录流程解析。我们为支持没有更新时间规则的来源，
会在 `information()` 中扫描完整目录推断更新；随后 `directory()` 原来又扫描一次。
瀚海书阁实机在首次 35 页目录成功后，第二轮扫描发生网络错误。

现在成功完成详情扫描后，第一次读取同一本书的目录复用已保存章节；消费后显式再次读取
仍会刷新，新一轮详情请求会清除旧标记。测试同时检查省去重复请求及后续刷新能读到新增章节。
这符合参考复用已取得数据的方向，但保留了我们在详情阶段推断更新的行为，不能说两边调度
已经完全一样。
