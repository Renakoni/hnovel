# 发现书籍预览与分类标签（#209）

发现展示已请求的书籍列表，例如“最近更新 →”下面直接显示书籍；箭头打开同一书单的结果页和分页。分类展示可点击的标签，题材、频道、完结状态、排行榜都可以是标签。同一个排行榜同时用于两页是合理的：两页展示形式不同。

## 最终样本

[discovery-routing-samples.json](../source-content/src/testFixtures/resources/discovery-routing-samples.json) 保存原始目录字段、文件 SHA-256、数组索引以及人工核对的预期。`index` 从 0 开始，并非文件物理行号。仅提取目录元数据，不复制 headers、账号信息、书籍或正文；书单 URL、分页模板和目录顺序保留原值。测试不访问这些站点。

## 分类规则与责任边界

1. 显式 `homepageModules` 优先，包括显式空数组；沿用既有模块类型、64 项上限及 `url` / `kindTitle` 解析。没有 `exploreUrl` 也能使用直接模块 URL。
2. 普通目录只看解析后的标题及最近一个空 URL 组标题。识别更新、新书、上架、热门、榜单、推荐等常见名称；兼容空格、装饰符号、全角字符及常见英文名称。只有组标题表示发现用途时，预览标题补上组名。
3. 自动首页取原顺序前 6 个候选，每项最多展示第一页的 6 本书，按完成顺序逐项发布。没有选中的其他目标仍在分类标签中，避免数百个细分榜单一次触发数百次请求。显式模块继续逐项读取全部声明的模块。
4. 每个已展示栏目都实际请求其书单；不会把未加载的题材目录画成空栏目。失败附在该项，保留诊断及重试，后续项继续；成功但为空时明确显示暂无书籍。取消、验证恢复、账号和修订失效沿用现有生命周期。
5. 分类保留目录中的全部 URL、原始 ID、标题、分组、未知名称及无名目标，不按名称合并不同目标。`ruleExplore.kind`、`ruleSearch.kind`、`lastChapter` 和 `bookSourceGroup` 都不是导航规则；无 URL 时不生成标签目标。
6. 静态能力和运行时共用目录结构解析器及分类器。静态阶段不执行脚本；动态目录、动态标题和损坏规则保留必要的候选能力或诊断入口。一次网络失败、验证前空目录不会写回永久能力禁用。
7. 空目录、纯占位、只有组标题不提供两项浏览能力。可操作的未限定范围控件保留在分类；结果页专用控件跟随对应书单。所有筛选继续使用原来的表单键和目标范围。

`RuleDiscoveryCatalogParser` 负责结构、ID、字段错误和限制；`RuleDiscoveryClassifier` 只判断用途和静态候选能力；`RuleDiscoveryProvider` 获取书单并发布预览。页面、来源绑定、规则解释器和分页各自保留既有职责。没有用途设置框架、站点域名特判、更新时间推算、全源重新排序或逐本详情请求。

## 七份 JSON 的口径

[discovery-routing-inventory.json](discovery-routing-inventory.json) 由既有离线统计脚本生成。共有 7,676 行，按完整定义去重为 5,885 个定义，其中小说 5,530 个；4,833 个声明搜索 URL，3,101 个声明目录，2,429 个没有目录。目录包括 1,436 个严格数组、71 个宽松数组、1,407 个文本目录、187 个 JS 目录。

这里的字段和关键词候选统计不是分类器全量验收，更不是联网通过率。“没有目录”也不必然等于“可搜索”，必须独立检查搜索能力。完整运行时分类以样本回归和实际解析结果为准；旧的六文件统计保留在 [discovery-inventory.json](discovery-inventory.json)，不改写历史实测证据。

## 复验

先用 `discovery_inventory.py` 对上述七文件生成独立报告，可与已提交的 inventory 比较。再执行：

```powershell
python -X utf8 source-compatibility/tools/discovery_routing_samples.py C:/Users/25799/Desktop --output routing-samples.json
```

提取工具逐文件检查固定 SHA-256，输出应与提交的样本完全一致。动态样本只核查候选能力；真实目录样本的静态内容通过同一生产解析器测试。补充的本地固定书单用于验证预览、来源身份、更多、筛选、分页、失败与取消，不将其描述为实站验证。
