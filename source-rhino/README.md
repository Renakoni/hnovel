# Rhino source runtime (#87, in progress)

Production Rhino is pinned to 1.8.1, matching the source-compatibility oracle. Each invocation owns an interpreted ContextFactory, an ES6 scope, an instruction counter, and a ClassShutter. Exceeding the instruction budget throws an internal Error and returns Timeout; script try/catch cannot suppress it. Thread interruption returns Cancelled. ContextFactory releases the context on every exit. An already-entered foreign Rhino context is rejected because it could bypass the owned observer.

Success carries bounded JSON text, not a live Rhino object. Serialization traverses plain objects and arrays and checks capacity before every append, including keys, punctuation and escaping. Strings, booleans, numbers and null retain their JSON types. Undefined/hole array values become null; undefined/function object properties are omitted; non-finite numbers become null. Cycles, excessive nesting and non-data host objects fail explicitly. Custom toJSON hooks are not invoked; this is a JSON-data result protocol, not a promise of arbitrary object serialization. Getters still execute under the instruction observer. A large nested value cannot hide behind `[object Object]`.

The synchronous HostBridge accepts JSON arguments and returns JSON data. Arrays, objects, numbers, booleans and null retain their types. Argument serialization and response conversion have a separate size/depth budget, and conversion never exposes Java wrappers. Script-visible bridge errors are catchable JavaScript errors without the original exception or credentials. `java`, `source`, `cache` and `cookie` expose explicit method ports over this same bridge; the host implements their capabilities. `key`, `page`, `baseUrl` and JSON `result` are invocation-owned data.

Pure helpers execute in the worker through the same bounded data conversion: `strToBytes`, `bytesToStr`, `base64Encode`, `base64Decode`, `base64DecodeToByteArray`, `hexDecodeToByteArray`, `hexDecodeToString`, `hexEncodeToString`, `md5Encode`, `md5Encode16`, `digestHex`, `digestBase64Str`, `HMacHex`, `HMacBase64`, `encodeURI`, `timeFormatUTC` and `timeFormat`. Byte arrays become signed numeric JS arrays. Charset arguments, Android Base64 flags, nullable byte decoding and odd/whitespace hex input follow the reference overloads. String Base64 decoding without numeric flags follows Hutool's permissive mixed-alphabet behavior. Date offsets are milliseconds; `timeFormat` uses the worker's locale/time zone. Unsupported algorithms/invalid arguments become catchable redacted errors, and oversized conversions fail the bridge budget. Helpers do not receive network/storage capabilities.

This is still an incomplete implementation of #87. The remaining crypto/compression/conversion/file tools, shared jsLib lifecycle and URL/rule integration remain required. Explicit method ports are not a claim that their host capabilities are implemented. PR #113 supplies the authenticated Android execution-service/broker binding. ClassShutter and instruction counting do not bound native Java regex, blocking host calls or the total process heap. Those require the real process boundary in #86; this module is not claimed to be a sandbox or complete Legado compatibility.

Validation: source-rhino tests cover typed nested bridge round trips, input/output bounds, catchable redacted errors, interruption during a result getter, context release/recovery and pinned Rhino JSON-data parity. Pure helpers have fixed hash/HMAC vectors, signed-byte/charset and URL/date contracts, plus differential tests against the reference's Hutool 5.8.22 dependency, including empty/null and permissive decoding behavior. Hutool is test-only. CI runs source-rhino:test and uploads its reports.
