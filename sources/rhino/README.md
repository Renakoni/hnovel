# Rhino source runtime (#87)

Production Rhino is pinned to 1.8.1; compatibility is also checked against the installed Reading app, which uses an HtmlUnit Rhino fork. Each invocation owns an interpreted ContextFactory, an ES6 scope, a deadline observer, and a ClassShutter. Like MD3, the instruction callback checks cancellation. It also checks the caller’s execution deadline; a fixed instruction total is not imposed by default because Rhino counts ordinary native RegExp scans as instructions. Callers can still set an explicit instruction cap. Exceeding either bound throws an internal Error and returns Timeout; script try/catch cannot suppress it. Interpreter recursion is limited to at most 1000 frames, matching the pinned engine limit; callers may lower it. Compile errors return Syntax; execution/stack exhaustion returns Runtime. Thread interruption returns Cancelled. ContextFactory releases the context on every exit. An already-entered foreign Rhino context is rejected because it could bypass the owned observer.

Android packaging retains Rhino's default `JavaToJSONConverters.STRING` behavior.
The optional `BEAN` converter requires five desktop `java.beans` introspection
types absent from Android; the host never selects it. The app's
[R8 rules](../../app/proguard-rules.pro) suppress only those five missing types,
without adding a JavaBeans implementation or changing script/JSON behavior.
PR CI builds the minified release APK and preserves shrinker diagnostics. Recheck
the converter and removed-code report when upgrading Rhino or changing this boundary.

The shared version catalog strictly pins Jsoup 1.16.2 for both JVM modules and the
APK, matching the reference selector runtime. Jsoup 1.22.2 automatically selects
RE2J when it is present; the app also needs that library for TXT parsing, but RE2J
rejects lookarounds and backreferences used by source CSS selectors. The Android
`packagedSelectorsKeepJavaRegexSemanticsWhenRe2jIsPresent` test exercises both rule
selectors and script DOM calls through the isolated worker. A module-only test
without the app's dependencies would miss this difference.

Scripts retain global completion-value semantics: `21*2` and `var n=21; n*2` return 42, while a raw top-level `return` is a syntax error. The pinned RhinoScriptEngine uses global evaluateReader. The compatibility ReferenceRunner wraps synthetic fixture bodies in an IIFE as a harness convention; this is not the production script entry contract. `book`/`chapter` have ordinary Object prototypes, and all bridge functions have Function prototypes supporting call/apply/bind, including null receivers. Binding a host method does not grant a new capability.

Success carries bounded JSON text, not a live Rhino object. Serialization traverses plain objects and arrays and checks capacity before every append, including keys, punctuation and escaping. Strings, booleans, numbers and null retain their JSON types. Undefined/hole array values become null; undefined/function object properties are omitted; non-finite numbers become null. Cycles, excessive nesting and non-data host objects fail explicitly. Custom toJSON hooks are not invoked; this is a JSON-data result protocol, not a promise of arbitrary object serialization. Getters still execute under the instruction observer. A large nested value cannot hide behind `[object Object]`.

The synchronous HostBridge accepts JSON arguments and returns JSON data. Arrays, objects, numbers, booleans and null retain their types. Argument serialization and response conversion have a separate size/depth budget, and conversion never exposes Java wrappers. Script-visible bridge errors are catchable JavaScript errors without the original exception or credentials. `java`, `source`, `cache` and `cookie` expose explicit method ports over this same bridge; the host implements their capabilities. `key`, `page`, `baseUrl` and JSON `result` are invocation-owned data.

Pure helpers execute in the worker through the same bounded data conversion: `strToBytes`, `bytesToStr`, `base64Encode`, `base64Decode`, `base64DecodeToByteArray`, `hexDecodeToByteArray`, `hexDecodeToString`, `hexEncodeToString`, `md5Encode`, `md5Encode16`, `digestHex`, `digestBase64Str`, `HMacHex`, `HMacBase64`, `encodeURI`, `timeFormatUTC` and `timeFormat`. Byte arrays become signed numeric JS arrays. Charset arguments, Android Base64 flags, nullable byte decoding and odd/whitespace hex input follow the reference overloads. String Base64 decoding without numeric flags follows Hutool's permissive mixed-alphabet behavior. Date offsets are milliseconds; `timeFormat` uses the worker's locale/time zone. Unsupported algorithms/invalid arguments become catchable redacted errors, and oversized conversions fail the bridge budget. Helpers do not receive network/storage capabilities.

`ScriptLibrary` retains a live, source/profile-owned jsLib scope. Following the pinned SharedJsScope/getRuntimeScope construction, initialization uses an empty scope over standard objects, without invocation/host bindings; its root is sealed after successful evaluation. Each invocation gets fresh bindings with the shared library as prototype. Nested mutable objects and closures survive; ordinary invocation declarations and book/result/page bindings do not. Function lookup keeps Rhino's lexical semantics rather than injecting current bindings into library closures. Calls using one library serialize across threads, and closing it drops the live scope and prevents reuse. A native data size failure after an operation starts discards the entire scope/realm so mutated DOM aliases cannot survive; the next invocation reinitializes the library. Pre-argument validation and pure crypto size failures preserve valid state. Initialization shares the invocation’s deadline, optional instruction cap and size budgets. Stored pure methods use the calling Context and current bridge budget, while stored host methods retain their original capability and must be rejected by a retired broker. Interrupted host failures return Cancelled even when the host throws a non-cancellation exception.

Eighteen legacy AES/DES/3DES methods plus randomUUID bring the pure-tool count to 36. These preserve pinned quirks: aesEncodeToString decrypts, desEncodeToString decodes raw ciphertext as UTF-8, aesEncodeArgsBase64Str keeps raw key/IV strings, aesDecodeArgsBase64Str decodes both, and 3DES ArgsBase64 overloads decode only the key. Decrypt input is ASCII hex when all characters qualify, otherwise permissive Base64. PKCS7Padding uses the equivalent PKCS5Padding JCE transformation; ZeroPadding is explicit. Algorithm support still depends on the platform provider. randomUUID generates a fresh version-4 UUID and does not expose a device identifier. The full method list is in ScriptCrypto.methods.

A library can contain multiple scripts, evaluated in order in the same scope before sealing it. Segment boundaries are preserved: a strict-mode directive in one downloaded script must not make later scripts strict. Aggregate source characters plus one per segment consume the initialization size budget. Downloading and caching the segments is the host's responsibility; Rhino never receives a network client or file path.

The #87 worker bridge profile is delivered with the merged #113 execution-service baseline. Login/browser/UI remain owned by #88/#89/#91 and production source routing by #90. Native regex, font/archive work and blocking host calls retain #86 process controls; ClassShutter and instruction counting alone do not bound native execution.

Validation: source-rhino tests cover typed nested bridge round trips, input/output bounds, catchable redacted errors, interruption during a result getter or failed bridge, context release/recovery and pinned Rhino JSON-data parity. Library tests compare lookup/shadowing with the reference scope construction, check mutable state across books, serialize 40 concurrent calls, reject foreign/closed library owners, bound initialization and apply current limits to stored methods. Pure helpers have fixed hash/HMAC vectors, signed-byte/charset and URL/date contracts, plus comparisons against the reference's Hutool 5.8.22 dependency, including empty/null and permissive decoding behavior. Modern crypto factories now use that pinned dependency in production behind explicit data methods. These dependency comparisons are not an independent algorithm oracle; fixed vectors and JCE/provider checks supply additional evidence. CI runs source-rhino:test and uploads its reports.

Validation includes JVM contract/differential tests and real API 24/35 isolated-process tests. ResponseContractTest compares response mutation and consumption with pinned Jsoup 1.16.2 via MockWebServer; DomContractTest compares DOM mutations and checks callbacks/forms/ranges. MetadataContractTest and MetadataWireTest cover lazy variables, size tiers, nullable writes and cross-stage metadata. These concrete probes are not an exhaustive engine-security proof.

Boundary construction captures Object/Array/Function/Error intrinsic prototypes before running a library. Native objects, arrays, functions and redacted errors are created from those captured prototypes, without calling a mutable global constructor. A library may shadow Object with null or replace Error with a throwing function without intercepting host data construction. The realm is retained and closed with its library; saved pure functions still use the currently calling Context and its limits. Prototype mutation within a source remains ordinary JS behavior; capturing constructor bindings is not a freeze of source-owned JavaScript state.

Network response views are native JS objects. Jsoup snapshots transport original bytes once; StrResponse transports decoded text and original byte length, since its raw body is consumed. Binary response construction charges raw bytes plus JSON metadata against the bridge budget, independently of Base64 transport expansion. Batches share the aggregate budget, and typed fetches use the shared 64 KiB default body ceiling; the 256 KiB IPC cap is separate. Retained mutable response state and derived header/cookie views recheck the complete owner with the current invocation budget. DOM attribute/dataset views retain their tree check as well. Jsoup response data methods include mutable headers/cookies, URL/method/charset overloads, parsing, buffering, signed-byte arrays and in-memory streams. StrResponse exposes consumed raw-body and transport metadata facades. Declared charset remains nullable for HTML meta detection.

Modern createSymmetricCrypto/createAsymmetricCrypto/createSign return native JS facades. They expose encrypt/decrypt byte/string/hex/Base64 methods, IV/key setters, key Base64 exports, sign/verify and explicit asymmetric block sizes. Setters return the same facade. Key/provider/cipher/stream Java objects are never exposed. Both asymmetric directions default to the public key, as in the pinned wrapper; false or explicit null selects private. Long RSA input requires explicit block sizes rather than silently adopting the different RSA subclass policy. Saved methods use the current invocation's bridge budget. Provider support remains platform-dependent. htmlFormat plus t2s/s2t bring the pure helper count to 39, preserves image tags and Android whitespace behavior, and is formatting rather than sanitization. Provenance is in THIRD_PARTY.md.

java.getString/getStringList/getElement/getElements evaluate selectors and nested script stages in the current ContextFactory, sharing input, variable writes, depth, rule budget and execution deadline. HTML/XML results expose closed worker-local DOM data/mutation methods and callback adapters; JSON elements retain their types. DOM handles serialize as markup between rule stages. Typed Java Class/Evaluator overloads and network factories are outside the data profile.

`org.jsoup.Jsoup.parse(html[, baseUri])` is an in-memory parser entry point over the
same DOM facades, available during jsLib initialization as well as ordinary rule
calls. It exposes no Java class or `connect` method. `java.setContent(content[, baseUrl])`
replaces the current invocation's selector input and returns the same `java` facade;
HTML text and JSON objects/arrays can feed subsequent selector calls. An explicit
base URL affects selector URL results and DOM views only, not the invocation globals,
book identity or host network authority. Omitted/null base URL retains the current
selector base. Explicit input to `getString` remains a temporary read. Replacing
content shares the existing budgets and does not carry state into another invocation.

ajax/connect/ajaxAll and resource-download ports evaluate @js:/<js>, @result stages, balanced expression templates and URL-option js in the worker. Option js receives the resolved URL and its authority as baseUrl. Nested computation uses the same instruction observer, temporarily restores invocation globals and bounds the complete expanded batch before host dispatch. Static key/page/baseUrl placeholders retain the established host compiler's charset-aware escaping for URL/body/header fields; arbitrary expression results are script-produced text. The host then compiles and authorizes the actual target. Browser options remain explicit deferred capabilities.

URL-option data uses the shared bounded `RequestOptionsJson` grammar, including single-quoted strings and embedded header/body JSON. Like `AnalyzeUrl`, an unreadable optional URL-options object falls back to the default request; malformed optional source headers retain the default identity. Explicit invalid header/body parameters still throw a catchable redacted Error and report `RequestSyntax`, including through nested request-template calls. Size and nesting limits are never ignored. Rule execution retains its original field; actual broker denials remain separate from parsing failures.

importScript/cacheFile/downloadFile/readFile/deleteFile use the merged source/account resource broker. importScript returns source text without evaluating it. readTxtFile obtains bytes and detects their charset in the worker unless an explicit charset is supplied. ZIP/RAR/7z entry and extraction tools, logical directory consumption and QueryTTF/replaceFont now execute through the same bounded resource boundary.

JsURL data properties/query maps and toNumChapter are implemented against the pinned reference, including full-width digits, duplicate query keys and first-match chapter output. Book/chapter changes and separate small/big variable writes are returned explicitly by rule tasks; they never change execution identity or implicitly write to Room.

Discovery invocations additionally install `ScriptDiscovery`: page-local `infoMap`, explicit callback data, read-only host snapshots, and bounded deferred UI intents. Native action methods cannot be retained for a later invocation. The current-source `searchBook` object overload is reduced to a source-local intent before JSON serialization. The host owns execution, navigation, and persistence; see [the #91 protocol and compatibility boundaries](../content/DISCOVERY.md).

Android consumers must retain the engine's reflection entry points when shrinking.
The JAR includes [R8 consumer rules](src/main/resources/META-INF/proguard/source-rhino.pro)
for Rhino's VM bridge, interpreter, regular expressions and lazy standard objects,
plus the public data methods that `ScriptDom` dispatches by reflection. Keeping
those methods does not add entries to the script API allowlist.
Without them a build can succeed while the isolated worker fails during startup
with `Failed to create VMBridge instance`. The rules preserve the existing runtime;
they do not enable Java class access or change script permissions and budgets.
[MinifiedSourceRuntimeTest](../../tests/benchmark/src/main/kotlin/indi/renakoni/nextvol/benchmark/explore/MinifiedSourceRuntimeTest.kt)
imports an offline fixture through the production source store and opens its
catalogue in a minified APK, including after a process restart. CI runs this on
API 35 in addition to the JVM and debug Binder tests.

`Packages.java.lang.Thread.sleep(milliseconds)` accepts one finite, nonnegative integer JS number (up to `Number.MAX_SAFE_INTEGER`) and returns null. Zero is a budget/cancellation checkpoint; negative, fractional, missing or nonnumeric arguments throw a catchable script error. Waiting counts toward the current invocation and rule deadlines, checks them at most every 10 ms, and exits on interruption. A timeout/cancellation cannot be swallowed by script `try/catch`. Retained library methods use the new invocation’s deadline; worker process termination remains the outer limit. `Packages.java.lang.System.currentTimeMillis()` accepts no arguments and returns host wall-clock epoch milliseconds, which can change with clock adjustments. These exports do not expose other Thread/System members, reflection or process control.
